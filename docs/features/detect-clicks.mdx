# Detect Clicks

home_widget offers functionality to check if your App was launched by clicking on an element in the HomeScreen Widget.

<Info>
Note that this is not for Interactive Widgets. For this please check the relevant documentation [here](/features/interactive-widgets).
</Info>

To detect this in your App there are two methods:

For when your App is started from the very background check:
```dart
HomeWidget.initiallyLaunchedFromHomeWidget();
```
this will return a `Future<Uri?>` with the Uri that was used to start the App.

When your App is already running all Widget clicks are broadcast to a Stream provided via:

```dart
HomeWidget.widgetClicked;
```
which is a `Stream<Uri?>` that you can listen to to detect App Launches from the Widget.

## Decoding Launches

`HomeWidget.initialLaunch<T>(decode)` and `HomeWidget.launches<T>(decode)` combine the two methods above and turn each Uri into a value of your own. `decode` receives the Uri and returns the launch it stands for, or `null` for a Uri it does not know:

```dart
enum WidgetLaunch { message, settings }

WidgetLaunch? decodeLaunch(Uri uri) => switch (uri.host) {
  'message' => WidgetLaunch.message,
  'settings' => WidgetLaunch.settings,
  _ => null,
};

// The launch the App was started with, or null.
final initial = await HomeWidget.initialLaunch(decodeLaunch);

// The initial launch first, if there was one, then every click while the App is running.
final subscription = HomeWidget.launches(decodeLaunch).listen((launch) {
  switch (launch) {
    case WidgetLaunch.message:
      // open the message
    case WidgetLaunch.settings:
      // open the settings
  }
});
```

`launches` subscribes to `widgetClicked` before it reads the initial Uri, so a click arriving in between is not lost. A Uri `decode` returns `null` for is skipped, which makes the result a `Stream<T>` without nulls. The scheme of the Uri handed to `decode` is lower-cased.

Any number of `launches` Streams can be listened to at once, each with a `decode` of its own. The initial launch is delivered once per run of the App: after one listener has decoded and received it, a Stream listened to later starts with clicks only. Call `initialLaunch` to read it again. An exception thrown by `decode`, and a failure to read the initial Uri, arrive as an error of the Stream, which keeps going with the clicks. A Stream listened to after a failed read reads the initial Uri again.

<Info>
Widgets generated with `home_widget_generator` get typed versions of both helpers. See [Widget Clicks](/generator/widget-url).
</Info>

## Platform Setup

In the following section you can learn how to add the necessary configurations to your native Widgets in order for clicks to be detectable by home_widget.

### iOS

Add `.widgetUrl` to your WidgetComponent
```swift
Text(entry.message)
    .font(.body)
    .widgetURL(URL(string: "homeWidgetExample://message?message=\(entry.message)&homeWidget"))
```
In order to only detect Widget Links you need to add the queryParameter`homeWidget` to the URL

### Android


Add an `IntentFilter` to the `Activity` Section in your `AndroidManifest`
```
<intent-filter>
    <action android:name="es.antonborri.home_widget.action.LAUNCH" />
</intent-filter>
```

Add the following modifier to your Widget (import from HomeWidget)
```kotlin
Text(
   message,
   style = TextStyle(fontSize = 18.sp),
   modifier = GlanceModifier.clickable(
     onClick = actionStartActivity<MainActivity>(
       context,
       Uri.parse("homeWidgetExample://message?message=$message")
     )
   )
)
```
