# Migration to 0.5.0

Regenerate your widgets, then check the changes below. Apart from the first one they only affect widgets that set a `widgetUrl`. The schema changes of this release are in the [generator migration guide](/generator/migrations/0.5.0).

## An annotation that does not compile fails generation

`generate` used to carry on when a `@HomeWidget(...)` annotation had an error, such as a parameter or constructor that no longer exists, and generated the widget without it or not at all. It now fails and lists what the analyzer reports inside the annotation, with line and column:

```text
home_widget/weather.dart: the @HomeWidget annotation does not compile, so no widget can be generated from it:
  7:13: The named parameter 'widgetUrl' isn't defined.
```

The same goes for a `const` variable of your project that the annotation refers to, such as `const tree = HWColumn(...)` passed as `widget: tree`, and for constants that one refers to in turn.

Fix the annotation, using the migration guide for anything that was removed. Errors elsewhere in the schema file, such as a reference to a helper that is only generated by this run, are not affected.

## Launch helpers need home_widget 0.10.1

The generated launch helpers call `HomeWidget.initialLaunch` and `HomeWidget.launches`, which `home_widget` has from 0.10.1. `generate` now fails for a widget that sets `widgetUrl` or contains an [`HWLink`](/generator/widgets/hw-link) when `pubspec.lock` resolves an older hosted `home_widget`:

```text
Widget "Weather": this widget opens the app with a URL, which needs home_widget 0.10.1 or newer; pubspec.lock resolves home_widget 0.10.0. Raise the home_widget constraint in pubspec.yaml and run `flutter pub get`.
```

Raise the constraint and run `flutter pub get`:

```yaml
dependencies:
  home_widget: ^0.10.0 # [!code --]
  home_widget: ^0.10.1 # [!code ++]
```

A path, git or workspace dependency is not checked.

## The helper reports taps as typed launches

The generated helper class gains `initialLaunch()` and `launches()`, which report a tap as a subclass of the generated sealed class `<Name>Launch`. The `Uri` helpers it had before, the static `widgetUrl` field, `initiallyLaunchedFromWidget()`, `widgetClicked` and `launchedFromWidget()`, are no longer generated, so code calling them stops compiling after the next `generate`. See [Uri Launch Helpers Removed](/generator/migrations/0.5.0#uri-launch-helpers-removed) for the replacement of each one.

## One widget URL for both platforms

The `androidWidgetUrl` and `iosWidgetUrl` fields of the generated helper class are gone, together with the per-platform `widgetUrl` settings they came from. See [Per-Platform Widget URLs Removed](/generator/migrations/0.5.0#per-platform-widget-urls-removed).
