# HWAppearanceAdaptive

`HWAppearanceAdaptive` picks a child layout based on how the system is displaying the widget: light mode, dark mode, or on iOS the Tinted, Clear (Liquid Glass), Lock Screen, and StandBy styles. Use it when the widget structure itself needs to change — for example, dropping a filled badge box on a Tinted or Clear iOS Home Screen. When only a color, image, icon, or text value changes, prefer [`HWAppearanceData`](/generator/appearance#hwappearancedata).

```dart
HWAppearanceAdaptive(
  light: HWRow(
    children: [
      HWImage(HWImageData('logoLight'), height: 24),
      HWText(HWString('title')),
    ],
  ),
  dark: HWRow(
    children: [
      HWImage(HWImageData('logoDark'), height: 24),
      HWText(HWString('title')),
    ],
  ),
  iosAccented: HWColumn(
    children: [
      HWImage(HWImageData.asset('assets/logo_mono.png'), height: 24),
      HWText(HWString('title')),
    ],
  ),
  iosVibrant: HWText(HWString('title')),
)
```

## Constructor

```dart
const HWAppearanceAdaptive({
  required HWWidget light,
  required HWWidget dark,
  HWWidget? iosAccented,
  HWWidget? iosVibrant,
})
```

Both `light` and `dark` are required. Every data field declared inside any slot becomes a field of the widget, as with [`HWSizeAdaptive`](/generator/widgets/hw-size-adaptive) and [`HWAdaptive`](/generator/widgets/hw-adaptive).

## Parameters

| Slot | Type | Default | Description |
| --- | --- | --- | --- |
| `light` | `HWWidget` | **required** | Layout rendered in light mode. |
| `dark` | `HWWidget` | **required** | Layout rendered in dark mode. |
| `iosAccented` | `HWWidget?` | `null` | Layout iOS renders on a Home Screen set to Tinted (iOS 18+) or Clear / Liquid Glass (iOS 26+) — WidgetKit's `.accented` mode. Ignored on Android. |
| `iosVibrant` | `HWWidget?` | `null` | Layout iOS renders on the Lock Screen and in StandBy — WidgetKit's `.vibrant` mode (iOS 16+; StandBy was not tested). Ignored on Android. |

## Selection and composition

Slots follow the same [selection order](/generator/appearance#selection-order) as `HWAppearanceData`: on iOS, `iosAccented` and `iosVibrant` take precedence when provided, and otherwise `light` or `dark` is picked by color scheme. Because Tinted, Clear, and Lock Screen all report a dark color scheme on iOS, omitting `iosAccented` or `iosVibrant` renders the `dark` slot there. Unlike `HWAppearanceData`, there is no missing-variant fallback between slots because each slot is a layout, not a value.

- `HWAppearanceAdaptive` composes with [`HWSizeAdaptive`](/generator/widgets/hw-size-adaptive), [`HWAdaptive`](/generator/widgets/hw-adaptive), and [`HWConditional`](/generator/widgets/hw-conditional) in either order.
- [`HWLink`](/generator/widgets/hw-link) and [`HWButton`](/generator/widgets/hw-button) work inside any slot, and the same link id may appear in multiple slots.
- On iOS, the layout switches live between light and dark mode, and renders the matching slot on Tinted, Clear, and Lock Screen placements. On Android, layout switches take effect at the next widget update — see [When the switch happens](/generator/appearance#when-the-switch-happens).

## Platform mapping

- **iOS:** generates a SwiftUI conditional branching on `widgetRenderingMode` (iOS 16+) and `colorScheme`.
- **Android:** generates a Glance conditional branching on the system night mode when the widget renders. `iosAccented` and `iosVibrant` are not emitted on Android.
