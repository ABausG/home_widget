# Migration to 0.5.0

Regenerate your widgets, then check the changes below.

A constant value is now a [data type](/generator/data#fixed-values) instead of a widget constructor. The constructors `HWText.fixed`, `HWText.fixedNumber`, `HWText.localized`, `HWIcon.fixed` and `HWImage.asset` are removed. The rewrite is mechanical, and the rendered widgets do not change: the regenerated Swift and Kotlin is identical.

| Removed | Replacement |
| --- | --- |
| `HWText.fixed('Hi')` | `HWText(HWString.fixed('Hi'))` |
| `HWText.fixedNumber(3)` | `HWText.number(HWInt.fixed(3))` |
| `HWText.fixedNumber(2.5)` | `HWText.number(HWDouble.fixed(2.5))` |
| `HWText.localized({...})` | `HWText(HWString.localizedFixed({...}))` |
| `HWIcon.fixed(Icons.add)` | `HWIcon(HWIconData.fixed(Icons.add))` |
| `HWImage.asset('a.png')` | `HWImage(HWImageData.asset('a.png'))` |

Parameters such as `style`, `textAlign`, `format`, `size`, `color`, `semanticLabel`, `width`, `height` and `fit` stay on the widget.

Taps that open the app are now reported as typed launches, which also covers the new [`HWLink`](/generator/widgets/hw-link). Three things changed for widgets that set a `widgetUrl`:

- [Per-platform widget URLs are removed](#per-platform-widget-urls-removed).
- [The launch helpers need home_widget 0.10.1](#launch-helpers-need-a-plugin-update).
- [The Uri launch helpers are deprecated](#uri-launch-helpers-deprecated).

## HWText.fixed Became HWString.fixed

Wrap the text in an `HWString.fixed`:

```dart
HWText.fixed('Hello', style: HWRoleTextStyle.headline()) // [!code --]
HWText(HWString.fixed('Hello'), style: HWRoleTextStyle.headline()) // [!code ++]
```

## HWText.fixedNumber Became HWInt.fixed and HWDouble.fixed

Use `HWInt.fixed` for an integer and `HWDouble.fixed` for a number with a decimal part. The number is still formatted on the device:

```dart
HWText.fixedNumber(10000) // [!code --]
HWText.number(HWInt.fixed(10000)) // [!code ++]
```

```dart
HWText.fixedNumber(0.5, format: HWNumberFormat.percent()) // [!code --]
HWText.number(HWDouble.fixed(0.5), format: HWNumberFormat.percent()) // [!code ++]
```

## HWText.localized Became HWString.localizedFixed

The locale map is unchanged and follows the same rules: it includes the default locale and has no placeholders.

```dart
HWText.localized({'en': 'Hello', 'de': 'Hallo'}) // [!code --]
HWText(HWString.localizedFixed({'en': 'Hello', 'de': 'Hallo'})) // [!code ++]
```

See [Localization](/generator/localization#two-kinds-of-localized-text) for how it differs from the stored `HWString.localized`.

## HWIcon.fixed Became HWIconData.fixed

```dart
HWIcon.fixed(Icons.favorite, size: 24) // [!code --]
HWIcon(HWIconData.fixed(Icons.favorite), size: 24) // [!code ++]
```

## HWImage.asset Became HWImageData.asset

`package` moves along with the path:

```dart
HWImage.asset('assets/logo.png', package: 'my_icons', width: 32) // [!code --]
HWImage(HWImageData.asset('assets/logo.png', package: 'my_icons'), width: 32) // [!code ++]
```

## Fixed Values Create No Stored Field

A `.fixed` value adds no `saveData` or `getData` parameter, no default and no preview value. It cannot be wrapped in `HWJson`, `HWTimedData` or `HWItemData`, used in `HWDataOnly`, or used as the condition of `HWBoolConditional` or `HWDataExists`. Each of these fails generation. See [Fixed values](/generator/data#fixed-values).

`HWBool.fixed` and `HWDateTime.fixed` are new. A fixed date takes an ISO 8601 string that names its zone, `Z` or an explicit offset such as `+02:00`, as in `HWText.dateTime(HWDateTime.fixed('2026-09-22T10:00:00Z'))`. A string without a zone fails generation.

## A Mistyped Key Points to HWString.fixed

Text passed to `HWString('...')` is a storage key. When it is not a valid key, such as `HWString('Hello world')`, the "Invalid data name" error now suggests `HWString.fixed`. The suggestion appears only for an `HWString` used on its own, not for one wrapped in `HWJson`, `HWTimedData` or `HWItemData`, and not for any other type.

## Per-Platform Widget URLs Removed

`HomeWidgetAndroidConfiguration.widgetUrl` and `HomeWidgetIOSConfiguration.widgetUrl` are removed. A widget has one `widgetUrl`, on the annotation, and both platforms open it:

```dart
@HomeWidget(
  name: 'Weather',
  widgetUrl: 'myapp://weather',
  android: HomeWidgetAndroidConfiguration(widgetUrl: 'myapp://weather/android'), // [!code --]
  android: HomeWidgetAndroidConfiguration(), // [!code ++]
  iOS: HomeWidgetIOSConfiguration(groupId: 'group.com.example.app'),
  // ...
)
class Weather {}
```

A widget that set the URL on one platform only moves it to the annotation, where it applies to both:

```dart
@HomeWidget(
  name: 'Weather',
  widgetUrl: 'myapp://weather', // [!code ++]
  android: HomeWidgetAndroidConfiguration(),
  iOS: HomeWidgetIOSConfiguration( // [!code --]
    groupId: 'group.com.example.app', // [!code --]
    widgetUrl: 'myapp://weather', // [!code --]
  ), // [!code --]
  iOS: HomeWidgetIOSConfiguration(groupId: 'group.com.example.app'), // [!code ++]
  // ...
)
class Weather {}
```

If the app has to behave differently per platform, branch on `Platform` where it handles the launch:

```dart
WeatherHomeWidget.launches().listen((launch) {
  if (Platform.isAndroid) {
    _openAndroidScreen();
  } else {
    _openWeather();
  }
});
```

To keep the Android widget from opening the app at all, `HomeWidgetAndroidConfiguration(openAppOnTap: false)` is unchanged. See [Widget Clicks](/generator/widget-url#widgets-that-should-not-open-the-app).

The generated `androidWidgetUrl` and `iosWidgetUrl` fields are gone along with the overrides.

## Launch Helpers Need a Plugin Update

The launch helpers of a widget that sets `widgetUrl` or contains an `HWLink` call `HomeWidget.initialLaunch` and `HomeWidget.launches`, which `home_widget` has from 0.10.1. When `pubspec.lock` resolves an older hosted version, generation fails. Raise the constraint and run `flutter pub get`:

```yaml
dependencies:
  home_widget: ^0.10.0 # [!code --]
  home_widget: ^0.10.1 # [!code ++]
```

## Uri Launch Helpers Deprecated

The static `widgetUrl` field, `initiallyLaunchedFromWidget()`, `widgetClicked` and `launchedFromWidget()` of the generated helper class are deprecated and will be removed in a later release. A tap now arrives as a subclass of the generated sealed class `<Name>Launch`, through `initialLaunch()` and `launches()`. See [Widget Clicks](/generator/widget-url#the-generated-launch-model).

| Deprecated | Replacement |
| --- | --- |
| `WeatherHomeWidget.launchedFromWidget()` | `WeatherHomeWidget.launches()` |
| `WeatherHomeWidget.initiallyLaunchedFromWidget()` | `WeatherHomeWidget.initialLaunch()` |
| `WeatherHomeWidget.widgetClicked` | `WeatherHomeWidget.launches()`, which emits the tap that started the app first |
| `uri == WeatherHomeWidget.widgetUrl` | `launch is WeatherWidgetTap` |
| `WeatherHomeWidget.widgetUrl` | `const WeatherWidgetTap().toUri()` |
| The `Uri` of a tap | `launch.toUri()` |

A typical listener changes like this:

```dart
late final StreamSubscription<Uri> _subscription; // [!code --]
late final StreamSubscription<WeatherLaunch> _subscription; // [!code ++]

@override
void initState() {
  super.initState();
  _subscription = WeatherHomeWidget.launchedFromWidget().listen((uri) { // [!code --]
    if (uri == WeatherHomeWidget.widgetUrl) _openWeather(); // [!code --]
  }); // [!code --]
  _subscription = WeatherHomeWidget.launches().listen((launch) { // [!code ++]
    switch (launch) { // [!code ++]
      case WeatherWidgetTap(): // [!code ++]
        _openWeather(); // [!code ++]
    } // [!code ++]
  }); // [!code ++]
}
```

The same goes for the launch that started the app:

```dart
final uri = await WeatherHomeWidget.initiallyLaunchedFromWidget(); // [!code --]
if (uri != null) _openWeather(); // [!code --]
final launch = await WeatherHomeWidget.initialLaunch(); // [!code ++]
if (launch is WeatherWidgetTap) _openWeather(); // [!code ++]
```

Code that still needs the `Uri`, such as a router that takes one, reads it from the launch with `launch.toUri()`.
