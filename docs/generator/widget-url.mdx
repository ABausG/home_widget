# Widget Clicks

Set `widgetUrl` on the annotation to have a tap on the widget open your app with that URL:

```dart
@HomeWidget(
  name: 'Weather',
  widgetUrl: 'myapp://weather',
  android: HomeWidgetAndroidConfiguration(),
  iOS: HomeWidgetIOSConfiguration(groupId: 'group.com.example.app'),
  widget: HWText(HWString('city')),
)
class Weather {}
```

The generator emits `.widgetURL(...)` on iOS and a Glance `clickable(actionStartActivity<MainActivity>(...))` on Android, so the same URL reaches the app on both platforms. Nothing has to be added to the native code by hand — including the Android manifest entry, which the CLI writes for you.

## Reading the URL in the app

As soon as a widget declares a `widgetUrl`, its generated helper class gains three members:

```dart
/// The URL a tap on the widget started the app with, or null.
static Future<Uri?> initiallyLaunchedFromWidget();

/// Every tap while the app is already running.
static Stream<Uri?> get widgetClicked;

/// The launch URL first (when there was one), then every later tap.
static Stream<Uri?> launchedFromWidget();
```

Listening to `launchedFromWidget()` covers both cases at once:

```dart
@override
void initState() {
  super.initState();
  _subscription = WeatherHomeWidget.launchedFromWidget().listen((uri) {
    if (uri != null) _openScreenFor(uri);
  });
}

@override
void dispose() {
  _subscription.cancel();
  super.dispose();
}
```

These are thin wrappers over [`HomeWidget.initiallyLaunchedFromHomeWidget()` and `HomeWidget.widgetClicked`](/features/detect-clicks) — reach for the plugin API directly if you would rather handle clicks from every widget in one place.

## The `homeWidget` query parameter

The plugin only reports a click whose URL carries a `homeWidget` query parameter, which is how iOS tells a widget tap apart from any other URL your app is opened with. The generator appends it for you when it is not already there, on **both** platforms, so the `Uri` the app sees is identical everywhere:

```
myapp://weather        →  myapp://weather?homeWidget
myapp://weather?city=1 →  myapp://weather?city=1&homeWidget
myapp://weather#today  →  myapp://weather?homeWidget#today
```

A URL that already carries the parameter is passed through untouched, and the rest of the URL is left exactly as written.

<Info>
The generator emits the URL string verbatim into the native code, but what the app receives is a parsed `Uri`, and `Uri.parse` lower-cases the scheme. A `widgetUrl` of `myApp://weather` therefore arrives as `myapp://weather?homeWidget` — expect the lower-cased scheme when you log or compare the `Uri`. Everything after the scheme keeps its casing.
</Info>

## Platform overrides

`HomeWidgetAndroidConfiguration.widgetUrl` and `HomeWidgetIOSConfiguration.widgetUrl` override the top-level value for that platform. Setting only one of them leaves the other platform on the top-level URL, or without a URL at all if there is none:

```dart
@HomeWidget(
  name: 'Weather',
  widgetUrl: 'myapp://weather',
  android: HomeWidgetAndroidConfiguration(widgetUrl: 'myapp://weather/android'),
  iOS: HomeWidgetIOSConfiguration(groupId: 'group.com.example.app'),
  widget: HWText(HWString('city')),
)
class Weather {}
```

Android opens `myapp://weather/android?homeWidget` here, iOS `myapp://weather?homeWidget`. The launch helpers are generated as soon as **either** platform has a URL.

## Without a `widgetUrl`

Leaving `widgetUrl` off does not make the widget inert — tapping it still opens your app, matching what iOS does by default for a widget that declares no `widgetURL`. On Android the generator emits a plain `actionStartActivity<MainActivity>()` for that case: the app launches, but the intent carries no URL, so no click is reported and the launch helpers are not generated.

<Info>
If you want to detect launches — to route to a screen, log the tap, or refresh on open — set a `widgetUrl`. That is what turns the tap into something the app can read.
</Info>

<Info>
On Android the URL is delivered through an intent-filter on your launcher activity. The CLI adds it to `AndroidManifest.xml` automatically when a schema sets a `widgetUrl` — if it cannot find a launcher activity it warns during generation, and the URL will not reach the app until the warning is resolved.
</Info>
