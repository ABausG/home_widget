# Data Types

`HWDataType` describes a single data field stored for a widget. You declare data fields in two places:

- Implicitly, by binding a widget to data (e.g. `HWText(HWInt('count'))`).
- Explicitly, via [`HWDataOnly`](/generator/widgets/hw-data-only) or `HWConditional` for fields that aren't rendered directly.

Each variant carries a `key` (the storage key) and an optional `defaultValue`.

```dart
@HomeWidget(
  name: 'Counter',
  widget: HWText(HWInt('count', defaultValue: 0)),
  android: HomeWidgetAndroidConfiguration(packageName: 'com.example.app'),
  iOS: HomeWidgetIOSConfiguration(groupId: 'group.com.example.app'),
)
class CounterWidget {}
```

The generated Dart helper exposes typed setters for each declared field, e.g. `setCount(42)` / `update(count: 42)`.

## Variants

| Variant     | Constructor                                | Dart type             | Description                                                                                  |
| ----------- | ------------------------------------------ | --------------------- | -------------------------------------------------------------------------------------------- |
| `HWString`  | `HWString(key, {defaultValue, previewValue})` | `String`            | Stored as a string in `SharedPreferences` / `UserDefaults`.                                  |
| `HWString.localized` | `HWString.localized(key, {required defaultTranslations, previewTranslations})` | generated translations class | Per-locale text. `defaultTranslations` maps locale tag to the text shipped with the widget; your app can override any locale at runtime. |
| `HWInt`     | `HWInt(key, {defaultValue, previewValue})` | `int`                 | Integer value.                                                                               |
| `HWDouble`  | `HWDouble(key, {defaultValue, previewValue})` | `double`            | Double / float value.                                                                        |
| `HWBool`    | `HWBool(key, {defaultValue, previewValue})` | `bool`               | Boolean value.                                                                               |
| `HWDateTime`| `HWDateTime(key, {previewValue})`          | `DateTime`            | A point in time, stored as an ISO-8601 UTC string. Rendered in the device's locale and time zone — see [Formatting](/generator/formatting). |
| `HWString.fixed` | `HWString.fixed(value)` | none | Constant text written into the widget. No stored field. See [Fixed values](#fixed-values). |
| `HWString.localizedFixed` | `HWString.localizedFixed(translations)` | none | Constant text translated at build time, one entry per supported locale. No stored field. See [Fixed values](#fixed-values). |
| `HWInt.fixed` | `HWInt.fixed(value)` | none | Constant integer. No stored field. |
| `HWDouble.fixed` | `HWDouble.fixed(value)` | none | Constant double. No stored field. |
| `HWBool.fixed` | `HWBool.fixed(value)` | none | Constant boolean. No stored field. |
| `HWDateTime.fixed` | `HWDateTime.fixed(isoString)` | none | Constant point in time, given as an ISO 8601 string that names its zone. No stored field. |
| `HWIconData.fixed` | `HWIconData.fixed(icon)` | none | Constant icon. No stored field. |
| `HWJson`    | `HWJson(key, child)`                       | `Map<String, dynamic>`| Stored as a JSON string. Wraps another `HWDataType` to address a nested leaf (e.g. `HWJson('user', HWString('name'))`). |
| `HWImageData` | `HWImageData(key, {previewAsset})` / `HWImageData.asset(path, {package})` | `ImageProvider`  | An image, saved at runtime or bundled as a Flutter asset. See [Image data](#image-data) below. |
| `HWIconData` | `HWIconData(key, {required icons, defaultValue, previewValue})` | generated icon enum | An icon chosen from a fixed set, rendered with [`HWIcon`](/generator/widgets/hw-icon). See [Icon data](#icon-data) below. |
| `HWItemData` | `HWItemData(data, {previewValues})` | the wrapped type's, on the generated item class | Wraps another type to read a field of the list item a builder is rendering, taking its key and the applicable default and preview. See [List items](#list-items) below. |

`HWString.localized` requires a `localization:` block on the annotation. Its generated setter takes a class with one required field per supported locale, and the widget picks the right one at render time. See [Localization](/generator/localization).

`HWInt` is typed `int` in Dart, `Int` in the generated Swift and `Long` in the generated Kotlin — a Dart `int` is 64-bit, so the Android side reads it as a `Long` rather than truncating it to an `Int`.

`HWDateTime` is typed `DateTime` in Dart, `Date` in the generated Swift and `java.util.Date` in the generated Kotlin. Storage is a plain string: `saveData` writes `value.toUtc().toIso8601String()`, and `getData()` parses it back into a **UTC** `DateTime` — call `.toLocal()` if you want the local one. The widget always displays it in the device's current time zone. See [Dates](/generator/formatting#dates). Its `previewValue` is a string the widget reads as written: spell it `yyyy-MM-ddTHH:mm:ss` with an optional fraction and `Z` or an offset, e.g. `2026-09-22T10:00:00Z`. Other ISO 8601 spellings generate with a warning and the preview shows no date.

## Fixed values

Every data type except the wrappers has a `.fixed` form for a value that never changes. Pass it to a widget in place of a stored type:

```dart
HWText(HWString.fixed('Last sync'))
HWText.number(HWInt.fixed(3))
HWText.number(HWDouble.fixed(2.5))
HWText.dateTime(HWDateTime.fixed('2026-09-22T10:00:00Z'))
HWIcon(HWIconData.fixed(Icons.favorite))
HWImage(HWImageData.asset('assets/logo.png'))
```

A fixed value is written into the generated native code. It creates no stored field: no `saveData` or `getData` parameter, no storage key, no default and no preview value. In the widget gallery it previews as itself. Rendering is the same as for a stored field holding that value, so `HWText(HWInt.fixed(3))` renders what `HWText(HWInt('n'))` renders with `3` saved.

| Type | Fixed form | Notes |
| --- | --- | --- |
| `HWString` | `HWString.fixed('Hello')` | Plain text. |
| `HWString` | `HWString.localizedFixed({'en': 'Hello', 'de': 'Hallo'})` | Translated at build time. Needs a `localization:` block and must include the default locale. See [Localization](/generator/localization). |
| `HWInt` | `HWInt.fixed(3)` | Formatted on the device when shown with `HWText.number`. |
| `HWDouble` | `HWDouble.fixed(2.5)` | Formatted on the device when shown with `HWText.number`. A value that is not finite (`double.infinity`, `double.nan`) is a generation error. |
| `HWBool` | `HWBool.fixed(true)` | Accepted wherever a stored `HWBool` is. |
| `HWDateTime` | `HWDateTime.fixed('2026-09-22T10:00:00Z')` | An ISO 8601 string that names its zone: `Z`, or an explicit offset such as `+02:00`. Formatted on the device, in its locale and the `timeZone` of `HWText.dateTime`. A string that does not parse, or names no zone, is a generation error. |
| `HWIconData` | `HWIconData.fixed(Icons.favorite)` | Takes any `IconData` constant. Anything else is a generation error. |
| `HWImageData` | `HWImageData.asset('assets/logo.png', package: ...)` | A bundled Flutter asset. See [Image data](#image-data). |

A fixed value has nothing to look up, vary over time or iterate, so these are generation errors:

- Wrapping it in `HWJson`, `HWTimedData` or `HWItemData`.
- Using it in [`HWDataOnly`](/generator/widgets/hw-data-only), which declares stored fields and would declare nothing.
- Using it as the condition of `HWBoolConditional` or `HWDataExists`, because one branch could never render. To pin a branch while you work on a layout, give the stored `HWBool` a `defaultValue` and `previewValue`.

Fixed values carry no key, and two of them are never merged with each other or with a stored field.

<Info>
`HWString('Hello')` and `HWString.fixed('Hello')` both compile, but the first one names a stored field called `Hello`. A key must start with a letter and contain only letters and digits, so text such as `HWString('Hello world')` fails generation with an error that points you to `HWString.fixed`. A single word passes as a key and renders empty until a value is saved.
</Info>

## Defaults

When a `defaultValue` is provided it's used both in the generated Dart helper and on the native side when the key is missing from storage. Without a default, the read path returns `null` (or the language's optional equivalent).

`HWImageData` and `HWDateTime` are the exceptions: neither supports a `defaultValue`. A missing image simply renders nothing — see [`HWImage`](/generator/widgets/hw-image) for a placeholder pattern using `HWDataExists`. A missing date renders as empty text, and the same `HWDataExists` pattern gives it a placeholder.

A missing **number** follows the same rule: with no `defaultValue`, an `HWInt` or `HWDouble` bound to an `HWText` renders as empty text rather than as a formatted `0` — see [Missing values](/generator/formatting#missing-values).

`HWString`, `HWInt`, `HWDouble`, `HWBool`, `HWDateTime` and `HWIconData` also take a `previewValue` next to their default; `HWImageData` takes a `previewAsset` and `HWString.localized` takes `previewTranslations` instead. `HWJson` and `HWTimedData` declare none of their own — they preview through the type they wrap or the leaf they address. Each of these is a sample shown only in the widget gallery, never on the home screen. See [Previews](/generator/previews).

## Image data

`HWImageData` describes an image slot rendered with [`HWImage`](/generator/widgets/hw-image). Supply runtime images through the generated `saveData(...)`, which takes an `ImageProvider` for each of them. `getData()` hands a top-level image back as the `String?` file path `saveData` wrote it to; only images nested in an `HWJson` group or in a timed entry come back from `getData()` as an `ImageProvider?`.

There are two forms:

- `HWImageData('key')` — a **runtime** image. Your app supplies it by passing an `ImageProvider` to the generated `saveData`.
- `HWImageData.asset('assets/logo.png')` — a **bundled** image. The native widget reads the Flutter asset straight out of the installed app bundle when it renders, so there is nothing to call at runtime and the image is there before the app has ever been launched. Asset images get no `saveData`, `deleteData` or `getData` entry. Pass `package:` to use an asset from a dependency: `HWImageData.asset('assets/logo.png', package: 'my_icons')`, mirroring `Image.asset`.

`HWImageData.asset` is the fixed form of an image and has no separate `.fixed` constructor. An asset image takes no key: two asset images in one widget that would be indistinguishable are reported as a generation error, and combining `package:` with a manual `packages/<package>/` path is one too.

Asset paths are checked when you run `home_widget generate`: app assets must exist and be declared under `flutter.assets`, and package assets must exist inside the resolved dependency — package assets are only checked once the dependency is resolved in `.dart_tool/package_config.json` (i.e. after `pub get`); if it isn't resolved yet, the check is skipped.

Binding an `HWImageData` to a text-only widget (e.g. `HWText(HWImageData('avatar'))`) is a generation error — an image is not display text. Use `HWImage` to render it.

A runtime image can also be wrapped in `HWTimedData` to swap pictures on a schedule — `HWImage(HWTimedData(HWImageData('slide')))`, see [Time-based images](/generator/timed-data#images) — or sit at the leaf of an `HWJson` group so a picture travels with the rest of a record: `HWImage(HWJson('contact', HWImageData('avatar')))`, see [Images at a JSON leaf](#images-at-a-json-leaf). Only `HWImageData.asset` is rejected inside either wrapper: an asset ships with the app, so there is nothing to store and nothing to vary.

## Icon data

`HWIconData` describes an icon chosen from a fixed set, rendered with
[`HWIcon`](/generator/widgets/hw-icon):

```dart
HWIcon(
  HWIconData(
    'mood',
    icons: [Icons.wb_sunny, Icons.cloud, Icons.umbrella],
    defaultValue: Icons.wb_sunny,
    previewValue: Icons.cloud,
  ),
)
```

- `key` — the storage key, like any other data type.
- `icons` — required, non-empty list of `IconData` constants the field can ever hold. Every icon
  must come from the same icon font family (`Icons.*` and `CupertinoIcons.*` cannot be mixed in one
  list) — a generation error names the field and the offending icon otherwise. No two of them may be
  the same glyph either: Flutter's aliases (`Icons.airplanemode_active` and
  `Icons.airplanemode_on` are both `0xe06e`) store identically, so listing both is an error.
- `defaultValue` / `previewValue` — optional `IconData` constants, and must each be a member of
  `icons` when given.

For each `HWIconData` field, the generated Dart helper emits an enum named
`<WidgetClassName><FieldKeyPascal>Icon` with one value per listed icon, each exposing an `icon`
getter that returns the original `IconData`. `saveData(...)` takes this enum rather than a raw
`IconData`, so only an icon actually declared in `icons` can ever be saved — see
[Icons](/generator/icons#runtime-icons) for the full generated shape and an example. The name is
built from the field key alone, so two fields sharing a key — one `icon` under `HWJson('today', ...)`
and another under `HWJson('tomorrow', ...)` — share one enum holding the union of both lists.

An `HWIconData` value is stored as the icon's Unicode code point. A field with no stored value and
no `defaultValue` renders nothing, exactly like a missing `HWImageData`. It works nested inside
`HWJson` and `HWTimedData`, the same as any other data type.

For a constant icon, use `HWIconData.fixed(Icons.favorite)`. It creates no field and generates no enum. See [Fixed values](#fixed-values).

## Nested JSON

`HWJson` lets you read a single leaf out of a JSON blob shared via `home_widget`. Chain `HWJson` to address deeper paths:

```dart
HWText(HWJson('user', HWJson('profile', HWString('name'))))
```

This reads `user.profile.name` from a JSON string stored under the `user` key.

Every segment of the path becomes a member of a generated `*JsonData` class, so besides the rules every data key follows it cannot be named `toJson`, `toString`, `hashCode`, `runtimeType` or `noSuchMethod` — the class already carries those. `fromJson` is free, since the class names a constructor rather than a member with it.

A leaf may also be an `HWString.localized`. The value found at the JSON path wins; when the path yields nothing, the leaf's `defaultTranslations` are resolved against the device locale instead — see [Localization](/generator/localization).

An `HWDateTime` leaf becomes a `DateTime` field on the generated `*JsonData` class and is stored as the same ISO-8601 UTC string as a top-level date field — see [Timed and JSON values](/generator/formatting#timed-and-json-values).

### Images at a JSON leaf

A leaf may be an `HWImageData`, so a picture travels with the rest of a record instead of needing a field of its own:

```dart
HWColumn(
  children: [
    HWText(HWJson('contact', HWString('name'))),
    HWImage(HWJson('contact', HWImageData('avatar'))),
  ],
)
```

The generated `ContactJsonData` then carries `final String? name` next to `final ImageProvider? avatar`, and one `saveData(contact: ...)` call persists both. Saving the group with a null image clears that picture, and `deleteData(contact: true)` removes the group together with every image it owns. See [`HWImage`](/generator/widgets/hw-image#images-inside-a-json-group) for the full contract.

`HWImageData.asset` is not allowed at a JSON leaf: an asset is read from the app bundle and never stored, so there is nothing for the blob to carry.

## List items

`HWItemData` reads a field of the item an `HWColumn.builder` or `HWRow.builder` is rendering, rather than a field of the widget's own data:

```dart
HWRow.builder(
  'forecast',
  maxItems: 5,
  item: HWText.number(HWItemData(HWInt('temperature', defaultValue: 0))),
)
```

It wraps an `HWString` (plain or localized), `HWInt`, `HWDouble`, `HWBool`, `HWDateTime`, `HWIconData` or runtime `HWImageData`, and takes its key from the type it wraps, along with the applicable default and preview — `defaultValue`/`previewValue` for most, `defaultTranslations`/`previewTranslations` for `HWString.localized`, and `previewAsset` with no default for a runtime `HWImageData`; see [`HWItemData`](/generator/lists#hwitemdata) for the full mapping. `previewValues` varies the sample from one gallery item to the next. The app saves the whole list through the generated helper, e.g. `saveData(forecast: [WeatherForecastItem(temperature: 21)])`. See [Lists](/generator/lists) for the generated item class, defaults, previews and the Android limits.
